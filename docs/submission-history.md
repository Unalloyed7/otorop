Шкала балла не указана. Не переводим его в проценты и не нормируем к диапазону 0–1 без подтверждения. «Лучшее решение» на странице собственной истории не устанавливает место в общем рейтинге. Колонка называется «Длительность загрузки»: нельзя считать всё это время чистым выполнением solution.py, поскольку состав показателя не раскрыт.

Оценённый сабмит подтверждает обработку платформой, но не доказывает, что все вопросы получили содержательные ответы и что внутри решения не было ошибок API или тайм-аутов. Ответ организаторов об отсутствии технических ошибок платформы был дан другой команде.

Исходный скриншот содержит сведения аккаунта и в репозиторий не копируется.

## Следующий шаг

1. Если сравнение ещё не запускалось, загрузить **psb-submission-baseline.zip**.
2. Сохранить показанные балл, длительность и статус. Результат этого кандидата пока не предоставлен.
3. Сравнить агрегированные результаты. Более высокий балл делает режим кандидатом для дальнейшей работы, но небольшая разница не доказывает улучшение: вариативность судьи и состав тестов не наблюдаются.
4. После выбора режима следующие изменения делать по одному. Локальные регрессионные ответы и отчёты можно получить на собственной доступной модели; заглушки проверяют программную логику, не качество DeepSeek.

Отключение самопроверки убирает отдельный вызов проверяющего для каждого сформированного черновика. Проверка существования источников, точности цитат, чисел и временной применимости остаётся. Это может как уменьшить лишние отказы, так и пропустить ошибочный вывод с настоящей цитатой; преимущество режима нужно проверять, а не предполагать.

Для новых обычных сабмитов без сравнительной задачи отчёт можно не включать:

```bash
.venv/bin/python tools/package_submission.py --verify-answer 1 \
  --output dist/psb-score-verify1.zip
```

В этом варианте не будет записи run-report.jsonl. Он не является парой с единственным изменением к уже отправленному диагностическому архиву, поэтому не подменяем им текущий сравнительный кандидат.
