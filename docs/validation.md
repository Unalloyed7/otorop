## Стыковка с поиском №1

Получен коммит `1e21cd8`: загрузчик documents.py, BM25-индекс retrieval.py, общий SchemaSearchBackend и проверки поиска. До интеграционных правок на установленной базе прошли все **103** проверки сокомандника и прежнего движка.

Проверены и исправлены три места на границе компонентов:

- `build_search` теперь выбирает `retrieval:create_search` по умолчанию, как веб, так и CSV используют этот backend. Ошибка не скрывается автоматическим переходом на первоначальный поиск.
- Backend возвращает candidates и не принимает решение об уточнении; движок теперь задаёт вопрос при неоднозначности и сохраняет выбор известного из истории договора.
- При преобразовании поиска в общие Evidence сохраняются признак текущей выгрузки закона, дата выгрузки и результат проверки условия допсоглашения. Историческая дата не превращает текущую выгрузку в историческую редакцию; not_applicable отличается от applicable.

Новые проверки проходят путь от настоящего поиска до Answer/CSV на выдуманных документах. Проверены обе стороны границы «после 1 октября», неизвестная дата, читаемый номер пункта и координаты цитаты, сохранение архивных правил и блокировка известной инструкции из найденной записки. Ответы моделей во всех этих проверках заданы заглушками; это не оценка DeepSeek.

В чистой копии подготовленных исходников на Python 3.12 без data/ результат — **94 passed, 21 skipped**: пропускаются только проверки, зависящие от материалов организаторов. Полный CLI с HTTP-заглушкой проходит и в этой конфигурации. Отдельно проверена передача current_only и даты выгрузки для всех **13 законов** из настоящего архива.

## Дополнительная самопроверка: сравнение с базовым вариантом

В синтетическом сценарии «неустойка без ограничения» генератор возвращает ошибочный вывод с настоящей цитатой. Числа совпадают, поэтому механическая проверка не видит потерю условия.

| Режим | Вызовы генерации | Результат сценария |
|---|---:|---|
| VERIFY_ANSWER=0 | 2: разбор + черновик | Ошибочный вывод пропущен. |
| VERIFY_ANSWER=1 | 3: разбор + черновик + проверка | Заглушка проверяющего исключила вывод; результат insufficient. |

Это контроль ветвления и стоимости в числе вызовов, не реальная оценка качества. На обоснованном ответе тестовый проверяющий сохраняет вывод. Для сравнения реальной модели нужны одинаковые вопросы, retrieval и параметры, раздельный учёт неверных выводов и лишних отказов, задержек, токенов и повторов API. Самопроверка не является гарантией истинности и по умолчанию включена как консервативная мера.

## Известные ограничения

- Поиск №1 теперь выбран по умолчанию: BM25 с эвристической нормализацией, связями и необязательным реранкером. Полнота выдачи и качество на скрытых вопросах не доказаны. Первоначальный поиск сохранён как явно выбираемый лексический резерв.
- Разрешение условий допсоглашений и юридическое следование проверяются моделью по полному контексту. Формальной проверки нет; обе модельные стадии могут ошибиться одинаково.
- Текущие и исторические вопросы теперь различаются; дата выгрузки не является периодом действия. Для прошлого/будущего используется узкий разбор прямо датированных положений из temporal.py; сложные исторические редакции требуют дальнейшей работы №1.
- Метаданные поиска №1 извлекаются эвристиками. Условия, даты и связи не считаются автоматически доказанными только потому, что попали в метаданные; сложные юридические изменения по-прежнему проверяются по найденным положениям.
- Один SearchFilters.event_date не моделирует несколько независимых дат. При необходимости требуется уточнение или согласованное расширение схемы.
- JSON-mode прокси не проверен; обычный текстовый JSON валидируется строго. Неверная структура даёт error, без угадывания результата.
- Числовая проверка консервативна: свободные вычисления и запись чисел другим способом могут быть отклонены. Это не калькулятор сроков и санкций.
- Защита от новых формулировок prompt injection и обманной истории не подтверждена живыми вызовами. Кодовый барьер покрывает известный маркер атаки, а не произвольные скрытые команды.
- Длинный ответ не обрезается посреди условий: если CSV с основаниями превышает лимит, записывается техническая ошибка. Для снижения таких ошибок нужно настроить краткость после реальных вызовов.
- Таймер RUN_TIMEOUT ограничивает обработку строк; длительное построение стороннего индекса должно укладываться в общий лимит запуска. №1 должен учитывать время индексации и не блокировать event loop.
- Качество на скрытых данных и поддержка реального прокси пока не проверены. Базовый веб/Docker реализован и проверен локально; публичный стенд и приёмка участником №3 остаются следующими шагами.
