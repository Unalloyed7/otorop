# Проверка веб-части

Дата: 10.11.2026. Это проверка локального прототипа, не результат официального LLM-судьи.

## API и общий движок

На Python 3.14 полный pytest завершился: **141 passed**. Из них 19 новых проверок API/упаковки; прежние проверки движка и поиска сохранены. Проверки выполнены после включения обновления поиска сокомандника `10a2b99` (гибридный поиск и даты). Для 21 проверки материалов организаторов локально установлена настоящая база. Есть одно предупреждение из установленного Starlette о будущем предпочтении httpx2 в TestClient; проверки проходят на закреплённом разрешённом HTTPX 0.28.1.

Проверены передача истории и даты в общий движок, отсутствие серверной памяти между запросами, lifespan клиента, каталог/скачивание, точные диапазоны в тексте, неизвестные ID, недоступность произвольных файлов, невалидные роли/история, размер тела, отсутствие отражения содержимого невалидного запроса, ограниченная очередь, отсутствие API-конфигурации и формирование конкурсного ZIP.

## Настоящий браузер

`tools/browser_smoke.py` использует Playwright 1.65.0 и установленный Chrome. Сервер, интерфейс, HTTPX-клиент, поиск и движок настоящие. Прокси модели — локальная HTTP-заглушка; данные вымышлены и создаются во временном каталоге, в рабочий веб не передаются.

Результат: **BROWSER_SMOKE_OK**.

- Desktop 1440×980: вопрос и ответ с основанием, открытие точного положения, продолжение с историей из трёх реплик, сохранение после обновления, чистый новый диалог, техническая ошибка API и возможность повтора.
- Mobile 390×844: отправка вопроса, боковое меню, исходный текст с выделением цитаты, закрытие панели, новый диалог.
- Emoji перед цитатой не сдвигает выделение: используется индексация Unicode code points.
- HTML пользователя не создаёт DOM-изображение; script в документе отображается текстом и не исполняется.
- Горизонтального переполнения и JavaScript page errors не обнаружено.

Полный отчёт и четыре снимка создаются в dist/browser-check. В репозитории сохранены снимки стартового экрана для передачи дизайна; это синтетическая проверка интерфейса, не ответы настоящей модели.

## Docker

Собран образ из Dockerfile на Python 3.12 slim-bookworm. `docker compose ... up -d --wait` завершился с состоянием **Healthy**. Проверены `/`, `/healthz`, `/api/status`, `/api/documents`: HTTP 200, каталог содержит настоящие **21 документ** из read-only монтирования data/.

Без конфигурации модели статус явно сообщает ready=false и model_configured=false; каталог остаётся доступным. Docker healthcheck проверяет жизнь процесса, готовность к вопросам нужно смотреть отдельно через /readyz. Сам факт Healthy не означает доступ к прокси.

## Упаковка

`tools/package_submission.py` создал dist/psb-submission.zip. Проверяется состав корня, синтаксис всех модулей, неизменность requirements.txt и воспроизводимость байтов архива. Данные, веб, ключи и демонстрационные ответы в архив не включаются.

Коммит `17470e1` клонирован в новый каталог. Создано новое окружение Python 3.12, зависимости установлены из requirements-dev.txt. Без материалов организаторов: **120 passed, 21 skipped**; pip check — **No broken requirements found**. Пропущены только проверки, требующие настоящую базу/открытые вопросы. ZIP собран и из этого клона, размер — 38 899 байт.

Из чистого клона выполнен `docker compose up --build -d --wait`: контейнер **Healthy**. Сначала без входных данных проверено documents_available=false. Затем установлен только knowledge-base.zip как документированный вход и контейнер перезапущен: каталог содержит **21 документ**, полный текст открывается по ID. Ключи и .env не переносились; модель остаётся явно неподключённой.

## Что не проверено
