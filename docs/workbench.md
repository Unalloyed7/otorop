# Рабочее место юриста

Дата: 12.11.2026. Веб использует тот же LegalAssistant, что и solution.py; юридическая применимость в браузере не рассчитывается.

## Запуск

Положите базу в data/knowledge-base.zip, настройте собственный доступ к модели через .env.example и выполните:

```bash
docker compose up --build
```

Откройте http://localhost:8000. Без настроенной модели доступны документы, импорт отчётов и локальная аналитика. Готовые ответы не подставляются. Официальный прокси организаторов по прежним условиям доступен только на платформе; новых локальных ключей у команды нет.

Прямой запуск:

```bash
.venv/bin/python -m pip install -r requirements-web.txt
.venv/bin/python -m uvicorn web_app:app --host 127.0.0.1 --port 8000
```

Приложение использует один процесс uvicorn. Блокировка файла не даёт незаметно запустить второй процесс с той же БД. Задания и отчёты хранятся в .state/workbench.sqlite; путь меняется WEB_STATE_DIR. В Docker подключён постоянный volume workbench-state в /state. Обычный docker compose down его сохраняет; не удаляйте volume, если нужны результаты.

## Путь проверки ответа

1. Задайте вопрос. В «Обстоятельствах и точности дат» можно независимо указать подписание договора, спецификации, поставку и рассматриваемое событие, включая месяц/год/диапазон. Условия формы договора имеют три значения: да, нет, не установлено.
2. Пока задание выполняется, видны этап и найденные источники с пометкой, что вывод ещё проверяется. Источники можно открыть, не принимая их за готовый ответ.
3. Откройте карточку утверждения. Она показывает субъект, правило, значение, событие отсчёта, период, условия, основания и ограничения. Отклонённые утверждения явно не включены в проверенный ответ.
4. «Сравнить положения рядом» открывает два выбранных источника, редакции и условия. Из любого положения можно перейти к точной цитате в полном оригинале.
5. Измените обстоятельства и нажмите «Перепроверить последний вопрос». Движок создаст новый проверенный результат. В интерфейсе будут отмечены добавленные и убранные основания. Сравнение исходников не заменяет расчёт применимости движком.

## Устойчивые задания

POST /api/jobs получает messages, as_of, scenario и idempotency_key. Повтор того же содержимого с тем же ключом возвращает существующий job_id; другое содержимое с этим ключом даёт 409. Очередь ограничена.

GET /api/jobs/{job_id} возвращает queued/searching/checking/ready/error/cancelled, события и окончательный Answer. POST /api/jobs/{job_id}/cancel отменяет ожидание и обработку в приложении; непроверенный ответ не публикуется. Поддержка фактической остановки генерации на стороне сервера модели зависит от этого сервера.

Браузер сохраняет ID и ключ до отправки запроса. После обновления страницы или разрыва связи он продолжает показ того же задания, без нового вызова движка. Готовый результат сохраняется и после перезапуска приложения. Если процесс прервался во время модельного вызова, задание становится error: повторный платный вызов автоматически не выполняется. Задание в очереди может быть продолжено при старте.

Владельца определяет отдельная случайная HttpOnly/SameSite cookie. На сервере хранится её хэш; чужие задания, запуски и оценки возвращают 404. Это изоляция сессий браузера, не корпоративная система учётных записей. Один профиль браузера использует одну сессию; потеря cookie закрывает доступ к прежним заданиям.

Прежний POST /api/chat оставлен для совместимости синхронных клиентов. Основной интерфейс использует задания.

## Панель локальных запусков

Кнопка «Сравнить запуски» доступна независимо от модели. Можно сохранить завершённое веб-задание или импортировать JSONL из локального RUN_REPORT / tools/evaluate_answers.py. Поддержан также JSON с records и configuration. Импорт не читает пути на сервере и не запускает модель. Размер файла ограничен.

Панель показывает версии движка (engine_sha256 и CODE_VERSION, если задана), модели и настройки, найденные источники, добавленные/убранные утверждения, причины отбрасывания, ошибки структуры, задержки и реальные счётчики HTTP-вызовов. Если старый отчёт не записал модель или настройки, значения не угадываются.

Для каждого сценария сохраняются ручная оценка корректности, признак лишнего отказа и комментарий. Они принадлежат выбранному локальному запуску. Официальные агрегированные баллы записываются отдельным блоком с именем архива, длительностью и заметкой о шкале. Скрытых серверных ответов и логов платформа не выдаёт; панель их не получает.

API панели: GET /api/runs; POST /api/runs/import; GET /api/runs/{id}; PATCH /api/runs/{id}/cases/{case_id}/rating; POST /api/jobs/{id}/save-run; GET/POST /api/official-scores.

## Проверка и ограничения

```bash
.venv/bin/python -m pytest -q
.venv/bin/python tools/browser_smoke.py
```

Браузерный сценарий использует временную вымышленную базу и локальную HTTP-заглушку вне рабочего контекста. Проверяются условный вывод, просмотр цитат, сравнение, повторная проверка, импорт, ручная оценка, обновление страницы во время задания и отмена. Эти проверки не измеряют качество DeepSeek.

Файлы примеров и проверок в конкурсный ZIP не входят. SQLite и локальные отчёты не добавляются в Git или Docker build context. Ключи не входят в конфигурацию диагностических отчётов. Модельная смысловая проверка способна ошибаться; точные координаты относятся к извлечённому тексту, визуальный просмотр оригинального PDF/DOCX не добавлялся.
